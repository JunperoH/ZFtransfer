# 测试记录

以下结论来自一台 Nikon Zf（固件 3.00）、一台 Android 16 手机、Android 14 虚拟机和本地模拟 PTP/IP 相机。其他机身、固件与手机组合仍需测试。

## 真机结果

- **AP：**手机连接 Zf 热点后，应用完成 PTP/IP 命令与事件通道初始化，列出相机中的 JPEG、NEF 和视频，并下载多张 JPEG/NEF。保存字节数与相机报告大小一致。
- **STA：**旧配置可被发现，但拒绝新的 PTP/IP 客户端（`InitFail 0x1`）。新建 STA 配置后，应用首次登记并由用户在相机上确认，之后可浏览并下载 JPEG/NEF 原图。清除应用数据会丢失客户端身份，旧 STA 配置可能再次拒绝连接。
- **蓝牙：**尚未在 Zf 上完成配对或 Wi-Fi 唤起；不要把该入口视为已验证的连接方式。

上述验证只证明测试文件的传输字节数相符；没有对每个下载文件与相机存储做端到端哈希对比。手机切换到系统相册后可能断开相机连接，返回应用时可重新连接。

## 本地复现

1. 执行 `gradlew.bat testDebugUnitTest assembleDebug`，安装 Debug APK 到虚拟机。
2. 在主机运行 `python tools/mock_ptpip_camera.py tools/MOCK_0001.JPG`。
3. 在应用中选 AP，手动填写虚拟机访问主机的地址 `10.0.2.2` 和端口 `15740`。
4. 连接后下载样本，核对保存文件与 `tools/MOCK_0001.JPG` 的 SHA-256。`tools/MOCK_0002.NEF` 只是合成字节样本，不是真实可解码的 NEF。

模拟器只覆盖通用 PTP/IP 浏览和下载，不模拟 Zf 的 STA 登记或蓝牙配对。`tools/mdns_ptp_probe.py` 可查看局域网 PTP 服务状态，`tools/sta_init_probe.py` 可发送单次初始化请求；这些工具不修改相机设置。

## v0.3.6 相册交互与缓存

在 Android 14 虚拟机的调试应用沙盒中放入 60 条模拟相机目录记录和对应缩略图（其中 10 条标记为新增），然后断线启动应用：60 张缩略图直接显示，新增筛选计数为 10。长按选中首张后纵向滑动，列表滚动且选中数保持 1；横向滑过一行后选中数变为 4。点“清除预览缓存”后，60 个缩略图文件清空，容量显示为 0 B。`testDebugUnitTest lintDebug assembleDebug` 通过。

这组模拟数据不验证真实 Zf 连接后的缩略图复用、系统相册目录里的已下载识别，也不代替手机上的手势体验复测。

v0.3.7 在同一虚拟机相册中检查了新增星芒、未下载箭头及筛选栏对应的对勾图标；三列网格中的状态标记可辨认。已下载的缩略图标记仍需用应用实际保存的照片在手机上复测。
